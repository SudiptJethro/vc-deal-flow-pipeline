# Deal Flow Pipeline

An automated sourcing pipeline for early-stage Indian startups in Consumer AI, Consumer Tech and HealthTech. It is a free, self-hosted take on what tools like Tracxn do: search public sources for new companies and their founders, classify them, rank founders by background signals, and serve everything through a filterable dashboard.

**[Live demo](https://sudiptjethro.github.io/vc-deal-flow-pipeline/dashboard/)** (synthetic data)

> **About the demo data.** Every founder, startup and website in `data/startups.json` and `dashboard/data.js` is fictional, generated by `scripts/make_sample_data.py`. The real pipeline output is personal data about individuals and is not published.

## The problem

Pre-seed investors in India see most companies only after they have raised or joined a well-known accelerator. The earliest signals are scattered: a "Show HN" post, a founder announcing they left Swiggy to build something, a new name on an incubator's portfolio page, a press note about a company exiting stealth. Checking those sources by hand every week does not scale.

This pipeline checks them automatically, merges the results into one deduplicated list, and puts the founders with the strongest background signals at the top.

## How it works

```
 Sources (10 scrapers)          Enrichment                     Storage + UI
 ─────────────────────          ──────────                     ────────────
 Hacker News (Algolia API) ┐
 Product Hunt (GraphQL API)│    sector classifier
 Accelerator portfolios    │    tier assignment (1/2/3)        Cloudflare D1
 News / media              ├──► funding-stage inference   ──►  Cloudflare Worker API
 Reddit, directories       │    dedupe + exclusion list        Static dashboard
 Web search (LinkedIn,     │
  X, Crunchbase, Tracxn)   ┘
        GitHub Actions (manual or scheduled) runs scripts/run_all.py
```

1. **Collect.** `scripts/run_all.py` runs ten source scrapers. Hacker News and Product Hunt use their public APIs. Accelerator and VC portfolio pages are read through Jina Reader, or rendered with Cloudflare Browser Rendering (`/api/render` on the Worker) when they need JavaScript. LinkedIn, X, Crunchbase and Tracxn are **not** logged into or crawled; the pipeline only reads public search-engine results that point at them.
2. **Enrich.** `scripts/enricher.py` classifies each company into a sector by keyword scoring, infers funding stage from text ("raised a pre-seed round", "bootstrapped", "Series A"), and assigns a founder tier.
3. **Deduplicate.** Named startups are deduplicated by name; profile-only records by LinkedIn URL. Startups already in your own pipeline can be skipped through an exclusion list.
4. **Store and serve.** Results are batch-upserted into Cloudflare D1 through its REST API. The Worker (`worker/src/index.ts`) serves them with KV caching, filtering, stats and CSV/JSON export. The dashboard reads from the Worker, or falls back to a static `data.js` file.

## Founder tiers

| Tier | Signal | Examples |
|---|---|---|
| 1 | Premier institution, top-company alumni, or clear traction | IIT/IIM/BITS, ex-Swiggy/Razorpay/CRED/Google, "revenue", "million users" |
| 2 | Some funding or accelerator signal | "raised", "pre-seed", "backed by", YC/Antler/SURGE mentions |
| 3 | Early, little public information | everything else |

Tiers are a triage tool for deciding who to look at first, not an investment score. Matching uses whole-word, case-insensitive rules, and search-engine boilerplate (such as a page title ending in "| LinkedIn") is stripped before matching so the host site is not mistaken for a former employer. The institution and company lists live in `scripts/config.py`.

## Repository layout

```
scripts/        Python pipeline: scrapers, enricher, orchestrator, sample-data generator
worker/         Cloudflare Worker (TypeScript): REST API, D1 schema, browser rendering
dashboard/      Static dashboard (HTML/CSS/JS): table and card views, filters, shortlist, export
data/           startups.json (synthetic in this repo)
.github/        GitHub Actions workflow that runs the pipeline
```

## Running it yourself

**Locally, no cloud needed:**

```bash
cd scripts
pip install -r requirements.txt
python run_all.py                 # scrape + enrich; writes data/startups.json and dashboard/data.js
```

Then open `dashboard/index.html` in a browser. Without a search API key the pipeline uses the DuckDuckGo library, which works for local runs. For reliable scheduled runs, set `SERPER_API_KEY` ([Serper.dev](https://serper.dev), free tier available).

**With Cloudflare (API + database):**

```bash
cd worker
npm install
npx wrangler d1 create deal-flow-db          # paste the id into wrangler.toml
npx wrangler kv namespace create KV          # paste the id into wrangler.toml
npm run db:migrate
npx wrangler secret put PIPELINE_SECRET
npm run deploy
```

Set `API_BASE` in `dashboard/app.js` to your Worker URL.

**With GitHub Actions:** add these repository secrets, then run the workflow from the Actions tab:

| Secret | Purpose |
|---|---|
| `CF_ACCOUNT_ID`, `CF_API_TOKEN`, `CF_D1_DATABASE_ID` | upload results to D1 |
| `SERPER_API_KEY` | search API (recommended) |
| `WORKER_URL`, `PIPELINE_SECRET` | browser rendering for JavaScript-heavy portfolio pages |
| `PH_TOKEN` | Product Hunt API (optional) |

The workflow is manual-only by default; uncomment the `schedule` block to run it on a timer. It writes results to D1 only and never commits them to the repository.

To refresh the demo data: `python scripts/make_sample_data.py`.

## Responsible use

- The output contains names and profile links of real people. Keep it private, do not commit it to a public repository, and handle it in line with the privacy laws that apply to you (for India, the DPDP Act 2023).
- Respect each source's terms of service and rate limits. Prefer official APIs (Hacker News Algolia, Product Hunt, Serper) where they exist.
- The pipeline does not log into, or bypass access controls on, any site.
